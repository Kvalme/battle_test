# Сборка и проверка

Требуются CMake 3.27+ и компилятор C++20. XML-парсер pugixml входит в `3rdparty/pugixml` и используется в header-only режиме. Сборка работает без сети.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/sw_battle_test scenario_4.txt
```

Приложение принимает путь к одному файлу сценария. Игровые события выводятся в stdout в исходном формате. Диагностика пишется в stderr. Seed генератора зафиксирован в `main.cpp` и равен 0. Побайтовое сравнение сценариев следует делать в одной среде сборки, так как разные реализации стандартной библиотеки могут давать разные последовательности распределения.

## Шаблоны юнитов

Шаблоны `assets/units/*.xml` встраиваются в бинарник. После изменения XML достаточно запустить сборку. Загрузчик также принимает отдельный файл с корнем `<unit>` или `<units>`. Каталог и встроенный набор используют файлы с корнем `<unit>`.

Внутренний формат XML изменился. Старые секции `<actions>`, `<target>`, `<damage>` и `<effect>` больше не поддерживаются. При миграции укажи в `<ability implementation="...">` ключ фабрики и перенеси параметры в её `<properties>`. Формат сценариев и событий совместим с исходным протоколом.

Команды `SPAWN_SWORDSMAN` и `SPAWN_HUNTER` используют соответствующие встроенные шаблоны. Тесты и инструменты могут создавать юнитов из дополнительных шаблонов через `World::spawn`.

## Что проверяет CTest

- Активности юнитов, выбор целей и группы fallback, путь и занятость, эффекты и порядок событий урона.
- Порядок старта CLI, диагностику реестра и конфигурации, вывод команд и запуск из каталога без XML.
- Тупик, повтор детерминированного состояния, случайную атаку с несколькими промахами, остановку по лимиту.
- Четыре исходных сценария и отдельный сценарий эффектов.

Тесты создают `World` и `Scheduler` рядом. Шаги и запуск боя идут через `Scheduler`.

Тест расширяемости использует фабрику `configured_probe` из `src/Features/Tests/` и отдельный шаблон в `tests/units/`. Один юнит получает два экземпляра с разными значениями нового параметра `markerText`. Тест проверяет порядок активации и оба значения через события. Тестовая фабрика подключается только к `sw_tests`.

## Форматирование и документация

При наличии clang-format во время конфигурации CMake добавляет цель `check-format`.
В CTest эта проверка не входит: результат зависит от версии clang-format.
Используется корневой `.clang-format`; рекомендуемая версия — 21.
Проверка охватывает C++ в `src` и `tests`, исключая сторонний и сгенерированный код.

```sh
cmake --build build --target check-format
```

Учебный C++ в `docs/examples` не входит в игровую сборку. Он показывает расширение,
которое можно перенести в Features. [Инструкция и XML](04_EXTENSION_GUIDE.md).
Схемы в руководстве построены через Graphviz; [команды перегенерации](diagrams/README.md).
