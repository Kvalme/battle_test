# Правила симуляции

## Активация и атака

Юниты активируются в порядке создания. Планировщик пропускает погибших. У живого юнита сначала срабатывают эффекты. Если он выжил, способности проверяются в порядке XML, и первая готовая способность выполняет одно действие.

Кандидаты сортируются по `EntityId`. Цель выбирается до проверки шанса `uniform(1, 1000) <= chance`. Запрос без кандидатов не расходует RNG. При неудаче спецатаки обычная атака той же группы использует ранее выбранную цель. Способности без группы выбирают цель самостоятельно. Если ни одна атака не готова, срабатывает следующая по списку способность, обычно `move`.

Рваные раны наносят урон `Rending` вместо `Strength`. На выжившей цели остаётся одна метка ран до окончания ближайшей обработки периодических эффектов цели. При нулевом `Rending` раны полезны на цели с активным ядом.

## Яд

- Каждый источник может держать один экземпляр яда на цели. Яды разных источников действуют независимо, в порядке первого наложения на цель.
- При первом наложении порция наносится сразу, остаются четыре активации цели. Повтор того же источника обновляет остаток до пяти будущих активаций, сохраняя силу, фазу и место яда в очереди. Само обновление не наносит урон.
- Сила фиксируется при наложении. Пять порций составляют `Poison / 5` каждая плюс 1 для первых `Poison % 5` порций. Например, `12 → 3, 3, 2, 2, 2`. Последовательность циклическая. При `Poison=0` спецатака пропускается.
- Активные раны удваивают каждую порцию яда, в том числе мгновенную. Яд засчитывается своему источнику даже после его смерти. Если порция убивает цель, дальнейшая обработка эффектов и её действие отменяются.

## Пространство и события

**Дистанция** между двумя юнитами — наименьшее число шагов от любой клетки первого юнита до любой клетки второго. Шаг можно делать в любую из 8 сторон, шаг по диагонали тоже равен 1.

Для двух клеток: `d = max(|x1 − x2|, |y1 − y2|)`.

Примеры:
- (2,2) и (3,3) — соседи по диагонали, d = 1.
- (2,2) и (5,3), d = max(3, 1) = 3.
- Соседние клетки (по стороне или по диагонали) дают d = 1.

Наземные юниты блокируют наземное перемещение. Воздушные юниты сохраняют позицию для расчёта дистанции и не блокируют клетки. Дальнюю атаку с `noAdjacent` блокирует живой наземный сосед на расстоянии 1, включая неуязвимого. Модификатор дальней атаки принадлежит цели. Нижняя граница дальности — 1. Неуязвимость исключает цель из атак, наносящих урон, и предотвращает урон при прямом запросе.

Марш состоит из шагов в любую из восьми допустимых соседних позиций. Путь ищется поиском в ширину с учётом занятых клеток. Если точка марша занята или недостижима, юнит идёт к ближайшей достижимой клетке (по Чебышёву) и ждёт там. Шаг делается, только если новая клетка ближе текущей, поэтому заблокированный юнит не ходит туда-обратно. Временно заблокированный марш сохраняется. Движение на несколько клеток за одну активацию публикует один `UNIT_MOVED` с итоговой позицией. При достижении точки публикуется один `MARCH_ENDED`.

Урон ограничен оставшимися HP. За одну операцию урон агрегируется по паре источник–цель. Разные источники публикуют отдельные `UNIT_ATTACKED`. Порядок при наличии событий: `UNIT_ABILITY_USED`, `UNIT_ATTACKED`, `UNIT_DIED`. Смерть публикуется один раз и освобождает клетки.

## Завершение

Симуляция останавливается, когда нет полезной атаки с положительной вероятностью, выполнимого движения и эффектов с будущей работой. Одинокая метка ран бой не продлевает. Проверка не меняет мир и не расходует RNG.

**Зацикливание.** Бой может повторяться по кругу без конца. Чтобы это поймать, `Scheduler` в начале каждого раунда берёт снимок состояния у `World::snapshot()` и хранит историю снимков. Если такой же снимок уже был, бой зациклился, и `Scheduler::run()` возвращает `Cycle`.

Повтор снимка доказывает цикл, только если снимок полный и раунд не зависит от случая. Поэтому `Scheduler` очищает историю, если в раунде:
- способность или эффект вернули `std::nullopt` из `cycleState()`, то есть не описали своё состояние
- на юните есть эффект с будущей работой (`hasPendingWork()`)
- был вызов RNG

Если цикл доказать нельзя, бой остановит аварийный предел активаций.

Предел по умолчанию — 10 млн активаций живых юнитов. После последней разрешённой активации планировщик ещё проверяет обычное завершение, а если активация закрыла раунд, то и цикл. Эти результаты дают CLI код `0`. Если требуется ещё одна активация, CLI возвращает `2` и пишет сообщение в stderr. Ошибки входа и конфигурации дают код `1`.
